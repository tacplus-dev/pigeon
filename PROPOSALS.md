- **Protect the `v*` tags with a ruleset** (2026-11-15, #2): a pushed `vX.Y.Z` tag now runs `.github/workflows/release.yml`, which publishes `ghcr.io/tacplus-dev/pigeon:X.Y.Z` and moves the line tag `X.Y`, with the workflow's own `GITHUB_TOKEN`. Anyone who can push a tag can publish an image. A repository ruleset on `refs/tags/v*` (create and update restricted to the manager app and maintainers, no deletion) keeps a release what the manager tagged on green main. tacplus-dev/looper's PROPOSALS.md asks for the same for its own tags (looper#115); the ruleset is a repository setting, so it is Jody's or the hub's to set, not a looper's.
- **Build the release image for amd64 too when a fleet needs it** (2026-11-15, #2): release.yml builds linux/arm64 only (`PLATFORMS`), as the fleets do (fleet-seatrials `images/pins.yaml`); the issue's first text asked for both. Turning amd64 on is one word in release.yml (`PLATFORMS: arm64 amd64`), and the GitHub release then carries both binaries. Do it when a fleet runs on amd64, not before: it doubles the build.
