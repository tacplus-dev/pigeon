# pigeon

The generic pigeon host, a tacplus platform service (registry id 107). It never runs as a
Deployment: the coop (github.com/tacplus-dev/coop) creates one Kubernetes Job per pigeon with
this image, an identity kernel minted for the run (`<service>/workloads/pigeon-<run_id>`, a
bootstrap token in the Job's Secret, `KERNEL_BOOTSTRAP_TOKEN_FILE`), and the run in its
environment (`PIGEON_RUN_ID`, `PIGEON_THREAD_ID`, `PIGEON_TENANT`, `PIGEON_KIND`, `PIGEON_CALLER`).

It serves no RPC. It lives on its run's thread of `coop.PigeonMessageBus.stream`: it says
`Ready`, does each `PigeonTask` its dog (the caller) puts there with the kind it was started as,
answers with a `PigeonResult`, and exits when the coop says the run has ended. Tasks from any
other sender are dropped; a task naming another kind fails `INVALID_TASK`.

Built-in kinds are the platform's: `echo.ping` (the result is the request) proves the round
trip. A product's kind, such as SeaBeam's Texas 811 filing, is that product's own host built on the
same protocol (`coop/proto/shared/pigeon.proto`).

`tacplus/` is generated by `tacplus build` and not committed.
